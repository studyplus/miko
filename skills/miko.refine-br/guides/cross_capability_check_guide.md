# ケイパビリティ横断チェックガイド

このファイルは、対象ケイパビリティの `business_rules.md` を他のケイパビリティと突き合わせて、境界・重複・用語・帰属の問題を検出する手順書である。この内容に正確に従うこと。

あなたは会話の文脈を持たない調査役である。**検出だけを行い、修正はしない。** 修正の是非は人間のドメイン判断であり、呼び出し元が扱う。

## 前提

呼び出し元から以下が渡される:
- 対象ケイパビリティ名
- 調査を担当する他ケイパビリティ名の一覧

読み込むファイル:
- `miko/<対象capability>/business_rules.md`
- 担当する各 `miko/<他capability>/business_rules.md`
- `miko/<対象capability>/harae.md`（あれば。重複ルールの検証履歴の偏りを見るため）
- `miko/glossary.md`（あれば）

プロジェクトのコードは読まない。BR の記述同士の突き合わせに集中する。

---

## 検査 1: 境界セクションの双方向整合性

対象ケイパビリティの `## 3. 関連ケイパビリティとの境界` と、担当する他ケイパビリティの同セクションを突き合わせる。

検出するもの:
- 対象が「他 cap Y に依存している / Y から借りている」と書いているのに、Y 側の境界に対象の記載がない
- 逆に、Y 側が「対象に渡している」と書いているのに、対象側に記載がない
- 双方に記載はあるが、内容が食い違っている（借りているものと渡しているものが噛み合っていない）

**特に重視するもの:** あるケイパビリティが他ケイパビリティの **内部状態** に依存していることが、依存先の境界セクションに書かれていない場合。依存先が自分の状態を変えるとき、依存元の存在に気づけない。この種の欠落は本番事故につながった実例がある。深刻度を「高」として報告する。

## 検査 2: 判断の重複定義

対象ケイパビリティのルール本文と、他ケイパビリティのルール本文を突き合わせ、同じ判断が別の ID で定義されているものを検出する。

- 一字一句同一の本文
- 語彙は違うが同じ条件・閾値・対象範囲を定めている本文
- 一方が他方の特殊化になっている（片方が広く、片方が同じ判断を狭い対象で繰り返している）

重複を検出した場合、`harae.md` を確認し、**検証履歴が片方にしかない** かどうかも報告する（片方だけ検証されている状態は、どちらを残すかの判断材料になる）。

## 検査 3: 同音異義語・衝突語

`glossary.md` と BR 本文を突き合わせる。

- 対象ケイパビリティの BR 本文に現れる語が、他ケイパビリティの BR では別概念を指している
- `glossary.md` の見出し語（システム全体で一意であるべき）と衝突している語
- glossary で別名が立っているのに、BR 本文が略称・衝突する側の語を使っている

**影響の見立てを添える:** 衝突している語のうち、一方がシステム全体の最重要概念（テナントに相当する語など）で、他方が狭い意味の語である場合、リネームの影響が大きい。どちらが広い概念かを明示する。

## 検査 4: 帰属が怪しいルール

対象ケイパビリティに書かれているが、隣接ケイパビリティに置く方が自然に見えるルールを検出する。

判断材料:
- ルールが主に他ケイパビリティの概念について語っている
- 他ケイパビリティの操作の定義に対応する操作しかない
- 対象ケイパビリティ側で「未決着」「暫定的にここに置く」等の自己申告がある

自己申告があるものと、誰も気づいていないものを区別して報告する。
